# House Price Prediction

A machine learning project that predicts house prices in Indian cities based on property features such as area, location, furnishing status, and more. The project includes a full data science notebook (EDA → cleaning → feature engineering → model training) and a **FastAPI** backend that serves the trained model through a REST API.

## Overview

The project is split into two parts:

1. **`HousePricePrediction.ipynb`** — a Jupyter notebook that loads a raw house-listings dataset, cleans it, explores it (EDA), engineers features, trains and compares three regression models, and exports the best one (`house_price_model.pkl`) along with a list of supported locations (`locations.json`).
2. **FastAPI backend** (`main.py`, `routes.py`, `schemas.py`, `model_loader.py`) — a lightweight API that loads the saved model and exposes endpoints to fetch supported locations and predict a house price from user-submitted property details.

## Dataset & Features

The dataset contains Indian real-estate listings with a price column (originally formatted as text, e.g. `"1.2 Cr"` or `"85 Lac"`) and various raw property attributes. During cleaning, the notebook:

- Parses `Amount(in rupees)` into a numeric `price_clean` column (handling `Lac`/`Cr` suffixes and `"Call for Price"` values).
- Extracts numeric values from `Carpet Area`, `Super Area`, and `Plot Area` (converting `sqm` to `sqft` where needed).
- Extracts a numeric floor number from the `Floor` column (`"Ground"` → `0`).
- Converts `Bathroom`, `Balcony`, and `Car Parking` to numeric and fills missing values with the median.
- Groups the top 50 most frequent locations and buckets the rest into `"Other"` (see `locations.json`).
- Removes outliers on carpet area, price, and price-per-sqft.
- Engineers two binary flags: `has_balcony` and `has_parking`.

**Final feature set used for training:**

| Feature | Type |
|---|---|
| `location_grouped` | categorical |
| `carpet_area_sqft`, `super_area_sqft`, `plot_area_sqft` | numeric |
| `Bathroom`, `Balcony`, `Car Parking`, `floor_num` | numeric |
| `Furnishing`, `Transaction`, `Ownership`, `Status`, `facing`, `overlooking` | categorical |
| `has_balcony`, `has_parking` | numeric (derived) |

**Target:** `price_clean` (house price in rupees)

## Model Training (Notebook)

The notebook builds a preprocessing + modeling pipeline using `scikit-learn`'s `ColumnTransformer`:

- **Numeric features** → median imputation
- **Categorical features** → most-frequent imputation + `OneHotEncoder`

Three models are trained and compared on an 80/20 train-test split:

| Model | Notes |
|---|---|
| Linear Regression | Baseline model |
| Random Forest Regressor | `n_estimators=300`, `max_depth=25` |
| Gradient Boosting Regressor | `n_estimators=100`, `learning_rate=0.1` |

Each model is evaluated with **MAE**, **RMSE**, and **R²**, and results are visualized with bar charts. The **Random Forest pipeline** is selected as the best-performing model and saved as `house_price_model.pkl` via `joblib`. The final grouped location list is also exported to `locations.json` for use by the frontend/API.

## Backend API

The FastAPI backend wraps the trained model behind two endpoints:

- **`GET /locations`** — returns the list of supported locations (from `locations.json`) so a frontend can populate a dropdown.
- **`POST /predict`** — accepts property details and returns a predicted price.

`model_loader.py` loads `house_price_model.pkl` and `locations.json` once at startup, and `routes.py` builds the exact feature row (including the `has_balcony`/`has_parking` flags) the model expects before calling `model.predict()`.

CORS is enabled for all origins in `main.py` to simplify local frontend development.

## Getting Started

### 1. Install dependencies

```bash
pip install fastapi uvicorn pandas scikit-learn joblib pydantic
```

### 2. Make sure the trained model exists

Run through `HousePricePrediction.ipynb` end-to-end (or place a pre-trained `house_price_model.pkl` and `locations.json` in the project root) before starting the API.

### 3. Run the API

```bash
uvicorn main:app --reload
```

The API will be available at `http://127.0.0.1:8000`, with interactive docs at `http://127.0.0.1:8000/docs`.

## API Reference

### `GET /locations`

Returns the list of grouped locations supported by the model.

**Response**
```json
{
  "locations": ["Other", "agra", "ahmedabad", "bangalore", "..."]
}
```

### `POST /predict`

Predicts a house price from property details.

**Request body**
```json
{
  "location_grouped": "mumbai",
  "carpet_area_sqft": 850,
  "super_area_sqft": 1000,
  "plot_area_sqft": 0,
  "Bathroom": 2,
  "Balcony": 1,
  "Car Parking": 1,
  "floor_num": 5,
  "Furnishing": "Semi-Furnished",
  "Transaction": "Resale",
  "Ownership": "Freehold",
  "Status": "Ready to Move",
  "facing": "East",
  "overlooking": "Garden/Park"
}
```

> Note: `Car Parking` is submitted using its exact key (mapped internally to `car_parking` via a Pydantic field alias).

**Response**
```json
{
  "predicted_price": 8500000.0
}
```
